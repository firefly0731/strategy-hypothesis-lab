## 2. 질문별 정리

### 2.1 Q6 — 크립토 특수성

**(a) 메이커 리베이트(마이너스 메이커 수수료)**
- 빗썸: API 스펙에 메이커와 테이커 요율 필드가 따로 있다 [S9]. 2024-02 기사에는 블랙 등급 회원에게 "메이커 리워드·특별 메이커 리워드"를 준다는 서술이 있다 [S23]. 현재도 운영 중인지, 요율이 얼마인지, 실질 수수료가 마이너스가 될 수 있는지는 **미확인**이다.
- 바이낸스 현물·선물: 공식 페이지가 접근 불가여서 **미확인**이다. 검색 결과 요약에서 본 LP 프로그램 리베이트 수치(-0.01%, -0.008%)는 원문을 열지 못했으므로 근거로 쓰지 않는다.
- 결론적으로 리베이트를 전제로 한 손익 설계는 지금 근거가 없다. 그래서 §3에서는 리베이트 0을 기준으로 계산했다.

**(b) 24시간 시장과 재고(인벤토리)**
- 가상자산시장은 국내 증시 휴장 기간에도 쉬지 않는다는 보도가 있다("국내 증시가 추석 연휴를 맞아… 문을 닫지만 가상자산시장은 쉬지 않는다") [S26].
- 함의(분석): 재고를 밤사이 정리할 마감 시각이 없다. 그래서 헤지는 체결 직후 즉시 하는 방식이어야 하고, 남은 재고 한도를 상시 감시해야 한다.
- 빗썸 쪽 공백도 위험이다. WS 120초 idle 종료 [S7], 한도 초과 시 1–10분 IP 차단 [S2], 공지 없는 한도 하향 [S1] 때문에 호가를 취소하지 못하는 구간이 생길 수 있다. 이 시간 동안 호가가 노출되는 위험을 kill-switch 설계에 반영해야 한다. 특히 취소 API가 차단돼도 이미 걸린 주문은 호가창에 남는다.

**(c) 거래소 간 재고 이동 제약**
- 원화 온램프: 빗썸은 제휴은행이 NH농협에서 KB국민으로 바뀌어 "3월24일부터 빗썸에서 가상자산 거래를 하려는 고객은 국민은행 계좌를 이용해야 한다" [S24](2025-01-13). 2026-06 기사에 따르면 "KB국민은행은 빗썸과 실명계좌 제휴를 맺고 있지만 계약 기간이 6개월로 단축되면서 올해 3분기 만료를 앞두고 있다" [S25]. 제휴가 현재 유지되고 있는지는 **미확인**이다.
- 법인 계좌: "법인 및 기관투자자는 가상자산거래소의 실명입출금계좌를 발급 받을 수 없어서… 거래가 제한되어 왔습니다"(로드맵 1단계는 시행, "2단계는 시행되지 않고 있습니다", 2026-01-22 기준) [S19]. 법인 명의로 운용할 계획이라면 우선 확인해야 할 사항이다.
- 원화 입출금 처리 시간, 일일 한도, 최초 입금 후 출금 지연: **미확인**(빗썸 공식 페이지 접근 불가).
- 출금 수수료: §1.1 표 참고 [S10]. 출금 허용 주소는 "100만원 이상 출금 가능한 주소"로 관리된다 [S12].
- 트래블룰(현행): "국내 VASP(거래소)는 100만 원 이상의 가상자산 이전에 대해 트래블룰을 적용", "FIU에 신고하지 않은 해외 VASP와의 거래는 원칙적으로 차단" [S22]. 빗썸 FAQ: 2022-03-25부터 "송/수신인 정보를 제공할 수 있는 VASP로의 이전만을 허용" [S2].

- 해석(분석): 원화로 표시한 USDT 가격(약 1,354–1,364원)이 이미 프리미엄을 거의 흡수하고 있다. 그래서 USDT를 경유하는 북에서 BTC 레그의 순수 베이시스는 몇 bp 수준이다. 은행 환율 대비 프리미엄(법정화폐 기준)은 환율 출처를 열지 않았으므로 **미확인**이다.

### 2.2 Q7 — 빗썸 제약 요약

- **수수료**: 메이커와 테이커를 구분하는 필드는 있다 [S9]. 실제 요율, 현재 쿠폰·이벤트, API 할증은 모두 **미확인**이다. 과거 자료는 쿠폰 0.04%, 미등록 0.25% [S23]. 2025–2026 이벤트로는 '익절 더블업' 같은 리워드 행사가 보도됐다 [S26].
- **레이트리밋**: §1.1 참고. MM 관점에서 가장 강한 제약은 한도 숫자보다 "동일 가상자산 초당 20회 초과 주문·취소 시 이용 제한 가능"이라는 조항이다 [S1]. 종목당 갱신·취소 횟수를 초당 20회보다 충분히 낮게 설계해야 한다. 정정 API가 없어서 호가 하나를 갱신하면 취소 1회와 신규 1회, 즉 2회가 든다 [S12].
- **틱**: §1.2 참고. ETH, XRP, SOL은 실측 스프레드가 1틱이었다. 이렇게 틱에 묶인 종목은 1틱이 4–10bp라서 호가 경쟁이 가격이 아니라 대기열 순위(queue priority)로 결정된다. BTC는 1틱이 0.12bp이고 스프레드가 21틱이어서 가격으로 경쟁하는 구조다 [S13].
- **WS 호가**: 상위 15단계 전체 스냅샷 [S5][S14]. 갱신 빈도는 **미확인**. 15단계 밖은 보이지 않고 L3가 없으므로, 자기 주문의 대기열 위치는 추정해야만 알 수 있다.
- **체결 스트림**: `ask_bid`로 공격 방향을 표시한다. `sequential_id`는 순서를 보장하지 않는다 [S6]. 마크아웃을 측정할 때는 `trade_timestamp`(ms)를 쓰고, 같은 ms 안의 순서는 확정할 수 없다는 점을 감안해야 한다.
- **Tardis**: 2026-09-23 이후 약 2개월치만 있다 [S14]. 장기 백테스트나 서로 다른 시장 국면 비교는 어렵다.

**(e) 쟁점 목록** (결론 없음)
1. 허수주문이 법문의 어느 요건에 해당하는가. 제10조③의 "시세를 변동 또는 고정시키는 매매 또는 그 위탁"인지, ④1호의 "부정한 수단, 계획 또는 기교"인지가 문제된다. 보도된 판결 [S18]은 "체결 가능성이 낮은 대량의 허수 매수 주문을 반복적으로 제출·취소"한 행위를 호가창 왜곡으로 인정했다. 다만 기사만으로는 적용 조항을 특정할 수 없다(**미확인**).

   - 거래량 급증(15배)
   - 체결 가능성이 낮은 대량 주문을 반복 제출하고 취소함
   - 호가창 하단의 '매수 벽'
   - "통상적인 투자 목적이라면 가격 상승 국면에서 일정 기간 보유 후 매도하는 방식이 합리적"이라는 비교
3. 유동성 공급(LP) 항변의 범위. [S18]에서는 이것이 핵심 쟁점이었고 해당 사안에서는 받아들여지지 않았다. 정상적인 양방향 호가 제공과 위장 거래를 무엇으로 구분하는지는 판결문 원문으로 확인해야 한다(판결문 미열람, **미확인**).
4. "시세"를 어느 거래소 기준으로 보는가. [S18]은 피고인이 실제 거래한 국내 거래소의 시세가 기준이라고 했다. 크로스거래소 전략에서 해외 가격을 기준으로 호가를 내는 행위가 이 개념과 어떻게 연결되는지가 쟁점이 된다.
5. 통정·가장매매(제10조②). 같은 계정이나 관련 계정의 매수·매도 호가가 서로 체결되는 경우, 즉 "권리의 이전을 목적으로 하지 아니하는 거짓으로 꾸민 매매"와의 관계가 문제된다. 빗썸 STP는 충돌 수량을 취소한다 [S3][S8]. 그런데 STP를 거쳐 취소되기 전까지의 주문 제출 자체가 어떻게 평가되는지는 **미확인**이다.
6. 마켓 간 가격 연동을 이용한 행위. 금융위 사례에 "코인거래소 內 마켓 간 (테더·BTC) 가격 연동을 이용한 사건"이 부정거래로 분류돼 있다 [S17]. 구체적인 행위 태양은 보도자료에 나오지 않는다(**미확인**).
7. 고빈도 API, API 키 대여. 금융위 사례에 "고빈도 API 매수·매도 및 허수주문", "API 키(Key) 대여를 통한 단기 시세조종"이 있다 [S17].
8. 거래소 감시와 주문 제한. 법 제12조의 상시 감시 의무 [S16], 빗썸의 "초당 20회 초과" 과도 주문·취소 제한 [S1], 금융위가 언급한 "동일 거래 반복시 주문을 제한" [S17]과 "초(秒) 단위 분석" [S17]이 해당한다.
9. 부당이득 산정(제19조⑥). 수수료와 체결가 구분이 산정에 영향을 준 사례가 있다 [S18].
10. 이 문서에서 열어 본 자료 중에는 개인이 양방향 호가를 반복 제출하고 취소한 행위만으로 허수주문이나 통정매매가 인정된 사례가 없다. 확인된 사례는 고가 매수·저가 매도, 허수 매수 벽, 발행재단 물량 처분 같은 행위가 함께 있었던 경우다 [S17][S18]. 이 외의 사례가 있는지는 **미확인**이다.
11. 부수 규제. 트래블룰 확대 [S20][S21], 김치 프리미엄 목적 해외 송금의 외환법 문제 [S22], 법인 실명계좌 제한 [S19].

## 3. 손익분기 스프레드 계산

### 3.1 정의와 공식

빗썸에서 메이커로 체결된 한 건(명목 N, KRW)이 바이낸스 헤지까지 끝났을 때 기대 손익을 명목 대비 bp로 쓴다.

```
E[π]/N = s − f_m − h − φ·c_fx − m − b
```

| 기호 | 의미 |
|---|---|
| `s` | 체결가와 공정가치 F 사이의 거리(반스프레드, bp). F는 바이낸스 가격 × KRW/USDT × (1+프리미엄 추정치) |
| `f_m` | 빗썸 메이커 수수료(bp) |
| `h` | 바이낸스 헤지 비용(bp). 테이커 헤지라면 테이커 수수료 + 반스프레드 + 슬리피지. 메이커 헤지라면 메이커 수수료 + 미체결로 인한 기회비용 |
| `c_fx` | KRW↔USDT 환전 1회 비용(bp). 빗썸 KRW-USDT 반스프레드 약 3.7bp [S13] + 빗썸 수수료 f_m |
| `φ` | 전체 체결 중 실제 환전·재조정이 필요한 비중. 양방향 흐름이 서로 상쇄되면 작아진다 |
| `m` | 마크아웃(역선택). 체결 후 τ초 뒤 F가 불리한 방향으로 움직인 기대값(bp) |
| `b` | 헤지 시점까지의 베이시스·프리미엄 변동 위험 프리미엄. 선물로 헤지하면 펀딩비와 선물-현물 베이시스도 여기에 들어간다 |

손익분기 조건(기대손익 ≥ 0):

```
s ≥ s* ≡ f_m + h + φ·(3.7 + f_m) + m + b          [bp]
s*_tick = s* × P / (10⁴ × tick)                   [틱]
```

빗썸 가격은 틱 격자 위에 있다. 스프레드가 1틱인 종목에서 최우선 호가에 합류하면 얻을 수 있는 s는 대략 0.5틱이다(F가 중간값이라고 가정할 때). 이 경우 손익분기 조건은 `0.5틱(bp) ≥ s*`가 된다.

### 3.2 가정 (모두 실험으로 측정하거나 확인해야 할 값)

- f_m 시나리오: F0 = 0bp(무료 이벤트 가정), F1 = 4bp(과거 쿠폰 요율 [S23]), F2 = 25bp(기본 요율 [S23], API 예시 값 [S9]).
- h 시나리오(바이낸스 요율은 **미확인**이라 가정값): H1 = 2bp(선물 메이커 헤지 가정), H2 = 6bp(선물 테이커 5 + 슬리피지 1 가정), H3 = 11bp(현물 테이커 10 + 슬리피지 1 가정).
- φ = 0.1(가정). b = 0(별도 실험 항목).
- **m(마크아웃) = 1 / 3 / 5 / 10bp는 순수 가정값이다.** §4의 실험으로 측정해야 한다.

### 3.5 해석 (가정에 조건부)

- 관측 반스프레드가 s*보다 큰 경우는 S_a(수수료 0, 메이커 헤지, m=1bp)에서 XRP(3.77)·SOL(4.94)·DOGE(3.73)뿐이다. ETH(2.05)와 BTC(1.22)는 S_a에서도 미달이다.
- 쿠폰 요율 4bp(F1) 이상이면 다섯 종목 모두 최우선 호가에서는 손익분기에 못 미친다. 이 경우 빗썸 스프레드 안쪽이 아니라 바깥쪽 깊은 호가로 물러서야 한다.
- 기본 요율 25bp(F2)에서는 메이커 호가 전략이 사실상 성립하지 않는다.
- 결정 변수는 다음 세 가지다. 모두 현재 미확인이거나 가정값이다.
  1. 실제 빗썸 메이커 요율 f_m(또는 리워드로 인한 순 요율)
  2. 실제 바이낸스 헤지 요율(VIP·리베이트 반영)
  3. 측정한 마크아웃 m
- 틱에 묶인 종목(ETH, XRP, SOL)은 s가 0.5틱으로 고정된다. 그래서 수익성은 대기열 위치와 체결 확률, 그리고 체결이 일어난 조건에서의 마크아웃(대기열 맨 뒤에서 체결되면 역선택이 더 크다)에 좌우된다. BTC는 틱이 매우 작아 가격 경쟁이 가능하다. 대신 반스프레드가 1.2bp밖에 안 돼서 비용 구조상 최우선 호가 경쟁은 불리하다.

## 4. 미해결 질문과 실험으로 측정할 값

1. **빗썸 실제 수수료**: 계정 등급별 maker/taker 요율, 쿠폰·이벤트 적용 여부, 메이커 리워드 유무. `GET 주문 가능 정보`(private)로 확인해야 한다. 사용자가 직접 실행해야 하며 이 문서 작성 중에는 호출하지 않았다.
2. **바이낸스 요율**: 현물·USDⓈ-M 선물의 VIP 구간별 maker/taker 요율, LP 프로그램 리베이트와 자격. 공식 페이지를 확인해야 한다(접근 불가였음).
3. **마크아웃 m(τ)**: τ = 100ms, 500ms, 1s, 5s, 30s 각각에 대해 빗썸 메이커 측 체결이 일어난 뒤 바이낸스 기반 F가 얼마나 움직이는지 측정한다. 공격 방향(`ask_bid`)별, 종목별, 시간대별로 나눈다. 원천은 Tardis 빗썸 trades·orderbook(2026-09-23 이후)과 바이낸스 데이터다. 그다음 소액 post-only 실주문 실험으로 실제 체결 조건부 마크아웃을 측정한다.
4. **대기열 동학**: 틱에 묶인 종목에서 최우선 호가 잔량이 얼마나 빨리 소진되는지, 15단계 스냅샷만으로 대기열 위치를 얼마나 정확히 추정할 수 있는지.
5. **WS orderbook 갱신 빈도와 지연**: 메시지 간격 분포, 빗썸 `timestamp`와 수신 시각의 차이. 이 세션에서는 WS 호스트가 차단됐다. Tardis의 local timestamp로 대체해 추정할 수 있다(Tardis 수집 위치는 도쿄 [S14]).
6. **헤지 지연과 슬리피지 h**: 빗썸 체결 통지(Private WS myOrder)부터 바이낸스 헤지 체결까지의 지연, 그리고 그 사이 F의 변동.
7. **베이시스 b**: KRW-BTC/BTCUSDT/KRW-USDT 프리미엄의 1분 단위 분포와 반감기. 여기서는 하루치 1시간 봉만 봤다(sd 3.7bp). 선물로 헤지할 경우 펀딩비와 선물-현물 베이시스도 측정해야 한다.
8. **φ(환전 비중)**: 순 흐름의 방향성이 지속되는지에 따라 재조정 주기와 비용이 달라진다. 출금 수수료 [S10]와 트래블룰 처리 시간도 실측해야 한다.
9. **레이트리밋 여유**: 종목당 초당 취소+신규 2회 × 호가 갱신 빈도가 "초당 20회" 제한 [S1]에 비해 얼마나 여유가 있는지 확인한다.
10. **틱 표 확정**: 1,000,000–2,000,000원 구간, 100원 경계 부근의 소수점 호가 원인, 공식 호가 단위 공지.
11. **원화 레일**: 국민은행 제휴 현황, 입출금 한도, 처리 시간, 법인 계좌 가능 여부 [S19][S25].
12. **법률**: 판결문 원문(서울남부지법 형사합의14부, 2026-02-04 선고, 사건번호 **미확인**), 시행령의 이상거래 정의, 금융위 고시. 양방향 호가 제공(LP)과 허수주문을 구분하는 판단 기준은 전문가 자문 대상이다.
