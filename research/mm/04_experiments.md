## E1. Binance→빗썸 선행 반응의 임펄스 응답과 지연 분포

**목적**: 빗썸 가격이 Binance 가격 충격에 얼마나 빨리, 얼마나 크게 따라오는지 측정해요. MM 관점에서는 빗썸 호가가 얼마나 오래 "stale" 상태로 남는지가 핵심이에요. 이 시간이 곧 역선택 위험의 크기예요.

**필요 데이터**: D1, D2, D3, D4, D5. 종목은 BTC, ETH, XRP, SOL, DOGE와 홀드아웃 3종목이에요. 기간은 최소 3개월이에요.

**방법**
1. Binance 기준가는 spot mid와 USDT-M mid 둘 다 써요. 빗썸 기준가는 KRW mid와 micro-price이고, 둘 다 USDT/KRW로 환산해요.
2. 이벤트 스터디를 해요.
   - Binance mid가 Δt = 100ms 안에 |r| ≥ k bp(k = 5, 10, 20) 움직인 시점을 충격으로 정의해요.
   - 빗썸 로그 수익률의 누적 반응 CIR(τ)를 τ ∈ {50ms … 60s}에서 구해요.
   - 반응 비율 CIR(τ)/r_Binance와, 반응의 50% · 90%에 도달하는 시간을 계산해요.
3. 연속 측정도 해요.
   - 비동기 체결 데이터에 Hayashi–Yoshida 리드-래그 추정을 써요. 지연 ℓ ∈ [−5s, +5s]에서 교차상관이 최대가 되는 ℓ*를 찾아요.
   - 같은 결론을 다른 방법(100ms 격자에서 이전 틱 보간 후 계산한 교차상관)으로도 구해서 비교해요. 프로토콜의 "두 가지 방법" 규칙이에요.
4. 지연 분포: Binance 충격을 수신한 뒤 빗썸 최우선호가가 처음 바뀔 때까지의 시간을 분포로 측정해요. 종목별, KST 시간대별, 변동성 3분위별로 나눠요.

**사전 등록 가설**
- H1-a: 빗썸 mid는 Binance 충격 뒤 **양의 지연**을 두고 같은 방향으로 반응한다. ℓ* > 0이고, 반응 50% 도달 시간의 중앙값이 > 200ms다.
- H1-b: 반응은 불완전하지 않다. 60초 안에 CIR이 충격의 80% 이상에 도달한다. 김프 변화로 인한 영구적 괴리는 따로 분리해요.
- H1-c: 지연은 저유동성 종목과 한국 야간 시간대(KST 02–08시)에 더 길다.

**채택·기각 기준**
- H1-a가 기각되면(중앙값 ≤ 100ms이거나 ℓ*가 통계적으로 0) **교차거래소 MM의 정보 우위가 없다**고 판정해요. E4 이후는 진행하지 않아요.
- 통과하면 지연 분포의 분위수(p50, p90, p99)를 E4 지연 모델의 입력으로 써요.

**비용·기간**: Tardis 데이터(2026-09-23 이후, 약 2개월)로 **예비 분석은 바로 가능**해요. 3개월 이상의 본 분석은 자체 수집이 필요하고 3개월 이상 걸려요. 분석은 1–2주예요.

## E2. 체결 후 1s / 10s / 60s markout (종목·시간대별)

**목적**: 빗썸에서 메이커로 체결됐을 때 **실제 역선택 비용 m**을 측정해요. `03`의 손익분기 스프레드 식에서 가장 중요한 미지수예요.

**필요 데이터**: D1(체결과 aggressor side, 호가), D2·D3(Binance 기준 fair value), D4.

**정의**: 메이커 쪽 부호 s_m(매수 메이커면 +1)과 체결가 p, 기준가 P_ref에 대해 다음과 같이 정의해요.
$$\text{markout}_h = s_m \cdot \frac{P_{ref}(t+h) - p}{p}, \quad h \in \{1s, 10s, 60s\}$$
- 기준가는 세 가지로 비교해요. (i) 빗썸 mid, (ii) 빗썸 micro-price, (iii) 환산한 Binance mid(선행 fair value)예요.
- 실현 스프레드(realized spread)는 메이커가 실제로 남기는 몫으로, `half-spread_at_fill + markout_h`예요. markout은 보통 음수라서 반 스프레드에서 깎이는 구조예요.

**세분화**
- 종목, KST 시간대(1시간 단위), 체결 크기 분위, 직전 1초 동안의 Binance 움직임(같은 방향 / 반대 방향 / 없음), 호가 불균형 분위로 나눠요.
- **조건부 markout**이 핵심이에요. "Binance가 이미 움직인 뒤 빗썸에서 체결된 메이커 주문"의 markout을 따로 봐요. 이게 lead-lag 테이커들에게 메이커가 털리는 비용이에요.

**사전 등록 가설**
- H2-a: 무조건부 10초 markout의 평균 절댓값은 빗썸 최우선 half-spread보다 작다. 즉 평균 메이커는 수수료 전 이익이다.
- H2-b: Binance 선행 움직임과 같은 방향의 테이커에게 체결된 메이커 주문은 10초 markout이 half-spread보다 크다. 즉 이 주문은 손실이다.
- H2-c: H2-b의 체결을 사전에 피할 수 있다면(E1의 지연 내에 호가를 취소하거나 이동), 남은 체결의 실현 스프레드는 메이커 수수료보다 크다.

**손익분기 기준값** (`03` §3)
$$s^* = f_m + h + \phi\,(3.7 + f_m) + m + b \quad [\text{bp}]$$
f_m은 빗썸 메이커 수수료, h는 Binance 헤지 비용, φ는 환전 비중(KRW-USDT 반스프레드 3.7bp 실측), m은 markout, b는 베이시스 위험이에요. E2는 이 식의 **m을 실측으로 대체**하는 실험이에요.

**채택·기각 기준**
- 종목별 10초 실현 스프레드 − 메이커 수수료 − 헤지 비용 ≤ 0이 **모든 세분 구간**에서 성립하면, 그 종목은 MM 후보에서 탈락이에요.
- H2-c는 **취소가 가능한 지연(E1의 p90) 안에** 회피 가능한 체결 비율이 얼마인지로 판정해요. 취소 지연은 `03`의 레이트 리밋과 API 응답 시간의 공개 문서값 및 가정에 근거해요.

**비용·기간**: E1과 같은 데이터를 써요. 분석은 1–2주예요.

## E3. 기존 MM의 호가 정책 역추정 (스프레드 회귀)

**목적**: 빗썸 호가창의 스프레드가 AS/GLFT 형태(변동성과 재고에 반응)인지, **호가 단위에 묶여 있는지**(tick-constrained) 확인해요. 묶여 있다면 경쟁은 가격이 아니라 **큐 우선순위(시간 순서)** 싸움이 돼요.

**필요 데이터**: D1(1초 스냅샷), D2(Binance 단기 변동성).

**방법**
1. 1초마다 다음 값을 기록해요.
   - 상대 스프레드 S_t(bp, tick 수)와, 스프레드가 1틱인 시간 비율
   - 최우선 잔량 Q^b, Q^a와 다단계 불균형
   - 직전 1분과 5분의 실현변동성 σ(빗썸, Binance 각각)
   - 체결 강도(직전 1분 체결 수)
2. 다음 회귀식을 추정해요.
$$S_t = \beta_0 + \beta_1 \sigma_t + \beta_2 \sigma_t^2 + \beta_3 \log(Q^b_t + Q^a_t) + \beta_4 \sigma^{Binance}_t + \beta_5 \text{TickRatio} + \varepsilon_t$$
   - AS와 GLFT 근사식에서 반 스프레드는 대략 $\frac{1}{\gamma}\ln(1+\gamma/\kappa)$ + (σ와 재고 관련 항)이에요. 그래서 β₁, β₂가 양수이고 유의하면 "변동성에 반응하는 MM이 존재한다"는 증거예요.
   - 정확한 식은 `01`을 참조해요.
3. 스프레드가 1틱에 묶인 시간 비율이 높은 종목은 회귀 대신 **큐 길이와 큐 소진 속도**(체결 강도 ÷ 잔량)를 분석해요.
4. 체결 강도와 호가 거리의 관계 λ(δ) = A e^{−κδ}를 적합해서 κ와 A를 추정해요. E4의 입력값이에요.

**사전 등록 가설**
- H3-a: ETH, XRP, SOL은 스프레드가 1틱인 시간 비율이 > 80%다. 즉 tick-constrained다. 근거는 2026-11-19 스냅샷에서 이 종목들이 1틱 스프레드(4.1 / 7.5 / 9.9bp)였다는 점이에요. 반면 BTC(21틱, 2.4bp)와 DOGE(6틱)는 가격 경쟁이 가능한 종목으로 분류해요 (`03` §1).
- H3-b: 중소형 종목은 스프레드가 σ에 양으로 반응한다(β₁ > 0, t > 3).
- H3-c: 빗썸 스프레드는 빗썸 자체 σ보다 **Binance σ**에 더 강하게 반응한다. 기존 MM이 Binance를 보고 호가를 낸다는 뜻이에요.

**채택·기각 기준**
- H3-a가 맞으면 해당 종목은 "가격 경쟁 불가, 큐 경쟁"으로 분류하고, E4에서 큐 모델의 민감도를 최우선으로 봐요.
- H3-c가 맞으면 교차거래소 MM 경쟁자가 이미 있다는 뜻이에요. 그러면 E1의 지연 우위가 줄어든다고 판단해요.

**비용·기간**: 분석 1주예요.

## E4. hftbacktest로 AS / GLFT 기본형 백테스트 (큐·지연 모델 명시)

**목적**: E1–E3에서 추정한 파라미터로 기본형 MM을 돌려, **수수료 차감 후 엣지가 남는지** 보수적으로 판정해요.

**도구**: [hftbacktest](https://hftbacktest.readthedocs.io/)를 써요. 큐 위치 모델과 피드·주문 지연 모델을 지원하고, GLFT 튜토리얼이 있어요. 빗썸 데이터는 hftbacktest 입력 형식으로 직접 변환해야 해요. 기본 제공 변환기는 Binance·Bybit 위주이고, 빗썸 지원 여부는 미확인이에요.

**전략 설정**
1. Fair value는 세 가지를 비교해요. (a) 빗썸 mid, (b) 빗썸 micro-price, (c) 환산 Binance mid에 E1의 반응 계수를 결합한 선행 fair value예요.
2. 호가 정책은 AS(유한 기간)와 GLFT(재고 한도, 점근 근사)를 써요. σ, κ, A는 E3의 발견용 기간에서 추정하고, γ는 5개 격자 값으로 사전에 고정해요.
3. 헤지는 재고가 한도를 넘거나 Binance fair value와 괴리가 생기면 Binance에서 테이커로 체결해요. 비용은 테이커 수수료 + 슬리피지 1bp + USDT/KRW 환산 비용이에요.
4. 수수료: **(범위 변경, 2026-11-19)** 국내 거래소는 제외했어요. 대상은 Binance USDC-M 무기한이고, 메이커 0bp, 테이커 4bp예요(사용자 제공). 헤지와 청산은 기본적으로 메이커로 하고, 테이커는 재고 한도를 넘을 때만 써요. 테이커 청산의 빈도와 비용을 핵심 판정 지표로 보고해요.

**체결 현실성**
- **큐 모델**: (i) 위험 회피형(내 앞의 잔량이 모두 체결된 뒤에야 내 주문이 체결된다고 가정), (ii) 확률형(power-law, log 확률 함수)을 써요. **채택 판정은 (i) 기준으로만 해요.**
- **주문 빈도 제약** (`03` §2)
  - 같은 종목에 초당 20회를 넘겨 주문·취소하면 이용이 제한될 수 있어요.
  - 정정(amend) API가 레퍼런스에 없어서, 호가 하나를 바꾸려면 취소 + 신규 = 2회가 들어요. 그래서 양방향 호가 갱신은 **종목당 초당 최대 약 5회**(양쪽 각 2회 × 5 = 20회)로 제한하고, 이 상한을 백테스트 엔진에 넣어요.
  - Private REST 한도는 초당 140회(다건은 초당 20회)예요.
- **지연 모델**
  - 피드 지연은 E1·D5에서 측정한 분포의 p50과 p90을 써요.
  - 주문 지연(전송과 응답)은 빗썸 문서 기준값 또는 보수적 가정으로 100 / 200 / 500ms를 둬요. 실주문 측정은 하지 않으므로 이 값은 **가정**이라고 명시해요.
  - Binance 헤지 주문의 지연도 별도로 둬요.
- **L2 큐 추정 오차**: 빗썸이 L3(주문 단위) 데이터를 주지 않으면 큐 위치는 추정치예요. 그래서 두 극단(위험 회피형, 낙관형)의 결과를 모두 보고해요. 그 차이가 곧 불확실성의 크기예요.

**사전 등록 가설**
- H4-a: 위험 회피형 큐 모델과 주문 지연 200ms에서, 발견용 기간 순손익(수수료, 헤지 비용, 환산 비용 차감 후)이 0보다 크다.
- H4-b: H4-a가 홀드아웃 종목과 뒤쪽 기간에서도 유지된다.
- H4-c: 선행 fair value(c)가 빗썸 mid(a)보다 체결 markout을 유의하게 개선한다.

**채택·기각 기준**
- **채택**: H4-a와 H4-b가 모두 성립하고, 다음을 모두 만족해야 해요.
  - 주문 지연을 500ms로 늘려도 순손익이 0 이상
  - 홀드아웃 3종목 중 2종목 이상에서 일별 손익 Sharpe가 1 이상
  - CPCV PBO < 0.3
- **기각**: 위험 회피형 큐 모델에서 순손익이 0 이하이면 기각해요. 확률형 큐 모델에서만 이익이 나는 경우는 "실거래 소액 검증 없이는 판정 불가"로 분류해요.
- **추가 확인**: 일별 취소·제출 비율, 호가 유지 시간 분포를 기록해요. `03`의 규제 쟁점(허수주문 판단 요소)과 비교할 자료예요.

**비용·기간**: 데이터 변환과 엔진 구성에 2–3주, 백테스트에 1–2주예요.

## E5. (선택) 김프와 헤지 베이시스 위험

**목적**: 빗썸 KRW 재고를 Binance USDT로 헤지할 때 **김프 변동이 만드는 손익 분산**과 자본 묶임을 측정해요.

**필요 데이터**: D1, D2, D4(일중과 일별), 거래소 간 이체 시간과 수수료(`03`).

**방법**
- 김프 = 빗썸 KRW 가격 ÷ (Binance USDT 가격 × 빗썸 USDT/KRW) − 1로 정의해요.
- 보유 기간별(1분, 1시간, 1일) 김프 변화의 분포와 꼬리(p99)를 구해요.
- 재고 회전 주기 동안의 베이시스 VaR을 계산하고, E4 손익에서 이 몫을 분리해요.

**사전 등록 가설**
- H5-a: 1시간 김프 변화의 표준편차는 E2의 10초 실현 스프레드보다 작다. 즉 헤지 베이시스가 MM 엣지를 잠식하지 않는다.

**채택·기각 기준**: H5-a가 기각되면, 재고 한도를 줄이거나 헤지 주기를 단축하는 조건 아래에서 E4를 다시 판정해요.
